## 5. 表需求规格

### 设计约定

以下约定适用于全部 13 张表，不在每张表重复说明：

| 约定 | 说明 |
|---|---|
| **主键** | `Base` 提供 `id: BigInteger, PK, autoincrement`（除 tag_current / tag_stats 见各自规格） |
| **时间戳** | `Base` 提供 `created_at` / `updated_at`（`DateTime(timezone=True)`, NOT NULL, default `utcnow`） |
| **租户列** | `TenantScopedBase` 提供 `tenant_id: String(64), NOT NULL, indexed` |
| **表名** | 每个 model class 必须**显式声明** `__tablename__`（Base 自动生成的是单数，DESIGN.md 用复数） |
| **枚举实现** | 使用 `String(N)` + `CheckConstraint`（非 SQL ENUM），配合 Python `enum.Enum` — 避免 ALTER ENUM 的迁移痛点 |
| **JSON 列** | 使用 `sqlalchemy.JSON`（MySQL 8 原生 JSON 类型） |
| **BLOB 列** | 使用 `sqlalchemy.LargeBinary` |
| **保留字处理** | MySQL 保留字列名重命名（见各表规格） |

| 属性 | 值 |
|---|---|
| **表名** | `tenants` |
| **中文名** | 租户表 |
| **用途** | 多租户根表，每个租户代表一个品牌/企业 |
| **继承** | `Base`（无 tenant_id，自身即租户） |

| `region` | `String(255)` | YES | NULL | 区域 |

> **设计说明**: DESIGN.md §12.2 schema 为 `tenants(id, name, brand, region, created_at)`，未列出 `code` 列。但 `TenantScopedBase.tenant_id` 为 `String(64)`，与 `tenants.id`(BigInteger) 类型不匹配。新增 `code` 列作为字符串业务标识，使 `tenant_id` 有逻辑引用目标。`code` 与 `tenant_id` 之间不建物理 FK（避免每张表都加 FK 的 DDL 膨胀），由应用层保证一致性。详见 §8 待确认问题 Q1。

**索引**:

**特殊约束**: 无

| Q8 | **recordings.store_id 的类型：String 还是 BigInteger FK？** | DESIGN.md schema 为 `store_id`，未定义类型。可能是门店代码（字符串）或自增 ID。 | `String(64)` — 门店通常有业务代码（如 `"SH001"`），且 stores 表不在 M1.4 范围。 | **否** — 可先用 String |
| Q9 | **0001_init.py 是原地修改还是新建 0002 迁移？** | 当前 0001_init.py 是哨兵占位。可以原地替换（M1.4 前无人依赖）或新建 0002（保留历史）。 | **原地替换 0001_init.py** — 项目尚在 M1，无生产数据，无需保留哨兵历史。 | **否** — 建议原地替换 |
| Q10 | **vectors_entity.entity_id 和 vectors_chunk.chunk_id 的唯一性约束范围？** | entity_id 无物理 FK（实体在 NetworkX 文件）。是否需要 (tenant_id, entity_id) 唯一？chunk_id 有 FK，是否需要 (tenant_id, chunk_id) 唯一？ | vectors_chunk: UNIQUE(tenant_id, chunk_id)。vectors_entity: INDEX(tenant_id, entity_id)（实体可能多次嵌入不同上下文，暂不加 UNIQUE）。 | **否** — 可先按建议实现 |
