# M10 验收与优化报告：接待对话智能工作台

> 2026-07-24 · 产品、前端、后端、数据、安全、性能与部署联合验收

## 结论

AudioGraphy 已从“录音文件分析”扩展为以 `Reception` 为核心的销售接待智能平台。本轮完成了多段短录音合并、长录音接待切分、对话单元切分、接待调听、三类图谱、状态聚合、标签矩阵、标签对比与溯源等主链路，并把它们纳入原平台的信息架构。

当前结论：

- 代码质量门禁通过：后端 2251 个测试通过、覆盖率 90.47%；前端 131 个测试通过。
- 三类图谱均已进入原平台菜单或详情上下文，不再是孤立演示页。
- Docker Mock 全栈可从空环境迁移到 Alembic head，并通过健康和就绪检查。
- 生产依赖未发现已知漏洞；前端开发工具链也已升级并清零 `npm audit`。
- Sites 演示数据有显式水印，真实数据库为空时会进入真实空状态，不再把模拟结果伪装为生产数据。

## 产品信息架构

```text
平台导航
├── 接待作业
│   ├── 接待中心
│   └── 录音管理
├── 对话洞察
│   ├── 状态路径          # 跨接待聚合
│   └── 标签洞察          # 对比、溯源、矩阵、图表
└── 知识与治理
    └── 全域知识图谱等原有能力

接待详情
├── 调听与切分            # 音频、时间线、转写、人工切分/合并
└── 关系与溯源
    ├── 关系图谱
    ├── 时序差分
    ├── 状态路径
    └── 溯源 DAG
```

这种分层将三个分析尺度分开：

1. 单次接待：回答“这次接待发生了什么、证据在哪里”。
2. 跨接待状态：回答“销售过程通常如何推进、在哪里回退或异常跳转”。
3. 多组标签洞察：回答“不同标签体系或版本如何合并、冲突和影响目标对话”。

## 已交付能力

| 领域 | 当前能力 | 关键边界 |
|---|---|---|
| 多录音组接待 | 按租户、门店、销售、时间和客户线索发现候选；服务端重算顺序与时间轴 | 不信任客户端时间线；未知时长不能静默自动接受 |
| 长录音切分 | 基于全量 Segment 指纹和短时签名令牌执行原子切分 | 源录音不改写；快照变化时拒绝旧提案 |
| 物理音频合并 | FFmpeg/ffprobe 装配、Range 回放、分块认证加密 | 输出路径受限；生成物可随源数据擦除 |
| 对话切分 | 从 ASR Segment 派生业务对话单元，支持人工 split 与相邻 merge | 乐观锁、证据裁剪、状态链重建 |
| 自动处理 | `merge → segmentation → tagging → ready` 持久化检查点与短租约 | 可幂等重入；源录音擦除会使旧运行失效 |
| 单次图谱 | 关系、时序、状态、溯源四模式 | 节点、边和证据均限制在当前返回窗口 |
| 状态聚合 | 主路径、一般路径、回退、异常与样本接待下钻 | 时间范围、筛选项、节点/边数量均有硬上限 |
| 标签洞察 | 多组、多版本、矩阵、冲突、覆盖、趋势、共现、目标对话 | 最多 8 个组版本；截断状态显式返回并展示 |

## 本轮关键修复

### UI 与交互

- 将接待详情图谱放入 `调听与切分 / 关系与溯源` 上下文页签。
- 将状态聚合和标签洞察放入平台 `对话洞察` 分组，并保留互相切换入口。
- 三类图谱统一为浅色、低噪声、语义社区化的视觉语言。
- 聚合状态页在平台侧栏存在时仍完整展示六阶段，不再横向裁切。
- 标签洞察的关系图、对比矩阵、图表分析具有真实选中状态，并支持页面内定位。
- 图谱节点、阶段与路径支持键盘激活；图标按钮补齐可读名称。
- 缺少证据时间码时禁用伪跳转；空、错、截断和未生成波形状态均有明确说明。
- 时间筛选改为本地时间转 ISO，并校验结束时间必须晚于开始时间。
- API 返回 401 时统一清理认证状态并回到登录页。

### 数据正确性与隐私

- `Recording` 和 `Reception` 均使用稳定 `agent_user_id` 授权，不再以销售姓名作为权限主键。
- 两阶段迁移只回填同租户、同姓名且唯一匹配的销售；重名、缺失和非销售用户保持未绑定并 fail-closed。
- 旧数据 `text_scrubbed IS NULL` 时统一执行运行时脱敏，空字符串仍视为权威清洗结果，不回退原始转写。
- 人工切分证据时同步裁剪 `start_ms/end_ms`，避免显示文本已裁剪但播放坐标仍指向旧片段。
- Workspace 只返回实际窗口内对话单元的标签、状态边与溯源关系，不生成悬空引用。
- 源录音擦除后同步清理派生对话、标签、状态、溯源和物理合并音频，并把自动运行重置为待重算。
- 认证中间件公共路径改为精确匹配，避免后缀匹配误放行任意路径。

### 性能与部署

- 前端页面按路由懒加载，AntV 图布局、渲染与核心包独立分块；初始 JS 设 250 KiB gzip 门禁。
- 向量查询保留 10 万条、128 维热查询 P95 自动门禁。
- 对话窗口、图谱关系、状态转移、标签矩阵、证据文本和筛选项均设置独立硬预算。
- 增加向量索引 LRU/TTL/字节上限缓存与租户图存储缓存。
- Docker 构建上下文由约 318 MB 降至约 50 KB；后端运行镜像不再安装 pytest、Ruff、mypy 等开发依赖。
- Compose 的应用、数据库、Adminer 与模型端口默认只绑定 `127.0.0.1`。
- Mock、CPU、单 GPU、多 GPU profile 与 Streaming VAD overlay 均可解析。

## 仍需在生产环境验证

以下事项不阻断当前代码验收，但不能由模拟数据或单机测试替代：

1. 对历史 `text_scrubbed IS NULL` 数据做离线批量回填，以消除首次读取的正则脱敏成本。
2. 把模型耗时较长的自动处理从 HTTP 请求生命周期进一步拆到独立任务队列/Worker，并完善跨进程进度推送。
3. 当接待量达到百万级时，对状态路径和标签洞察引入物化聚合或分析库，继续保留当前截断与钻取契约。
4. 使用真实租户、音频、时间码和加密文件完成 Range 回放、过期凭证刷新与 DSAR 物理擦除演练。
5. 补充移动端、200% 缩放、高对比模式和真实屏幕阅读器验收。

## 发布判断

当前版本满足“可评审、可演示、可在 Mock 全栈启动、可接真实数据继续联调”的发布条件。它不是带演示账号和预置业务数据的生产发行版；首次接入真实环境仍需创建租户和用户、导入录音，并按部署文档配置密钥和模型 profile。

详细领域不变量与接口约定见 [reception-intelligence.md](./reception-intelligence.md)，视觉验收见仓库根目录 `design-qa.md`。
